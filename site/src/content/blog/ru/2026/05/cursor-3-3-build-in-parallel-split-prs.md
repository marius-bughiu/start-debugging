7 мая 2026 года Cursor выпустил [версию 3.3](https://cursor.com/changelog/05-07-26). Этот релиз усиливает тот же сдвиг, на который уже намекала [предварительная версия TypeScript SDK](/ru/2026/05/cursor-typescript-sdk-programmatic-coding-agents/): агенты больше не являются единым потоком работы, привязанным к одному чату. Главные возможности, "Build in Parallel", "Split PRs" и переработанная поверхность ревью PR, толкают редактор ближе к мультиагентной IDE, где один человек контролирует несколько одновременных запусков.

## Build in Parallel превращает план в асинхронные субагенты

Планирование уже было частью цикла Cursor: вы набрасываете план, агент идёт по шагам. В 3.3 новое действие "Build in Parallel" берёт этот план, определяет независимые шаги и запускает асинхронные субагенты, которые работают над каждым из них одновременно. Cursor по-прежнему сохраняет порядок зависимых шагов, когда план подразумевает последовательность, так что вам не нужно вручную размечать граф.

Если вам ближе вкус CLI, есть команда `/multitask`, которая управляет тем же механизмом из чата:

```text
/multitask
- Wire the Stripe webhook handler
- Add a Polly retry policy around the OpenAI client
- Rewrite the README install section
```

Каждый пункт выполняется в собственном контексте субагента. Субагенты делят рабочее пространство через снимки, а не через общий буфер, поэтому две одновременные правки одного файла больше не конфликтуют. Субагент Explore теперь также принимает селектор модели (`model: opus`, `model: parent` или `disabled`), а это значит, что дешёвый шаг "найди релевантный код" может выполняться на меньшей модели, чем писатель.

## Split PRs нарезает один чат на несколько

Любой, кто давал агенту поработать час, знает эту боль: когда вы останавливаете его, диф покрывает четыре несвязанных изменения, и ревьюить это как один PR безнадёжно. Новое быстрое действие "Split into PRs" анализирует транскрипт чата, группирует коммиты по логическому смыслу и открывает по одному PR на группу. Cursor сохраняет независимость PR, если не обнаружит реальную зависимость, тогда он связывает их пометкой "depends on".

Перед разделением создаётся защитный снимок, и Cursor запрашивает подтверждение перед push.

## PR Review объединяет три вкладки в один поток

Третья часть, это переработанный вид PR прямо в редакторе. Три вкладки заменяют прежнее разделение между GitHub и панелью агента:

- **Reviews**: встроенные треды ревью и комментарии PR верхнего уровня с быстрыми действиями для ответа или принятия.
- **Commits**: сфокусированный список коммитов PR, чтобы вы могли пройтись по истории работы агента.
- **Changes**: дерево файлов плюс селектор, та часть, которая становится заметной, когда PR трогает сорок файлов.

Вместе эти три возможности обрисовывают то же направление, на которое указывал [TypeScript SDK от Cursor](/ru/2026/05/cursor-typescript-sdk-programmatic-coding-agents/): единица работы больше не "один промпт, один диф", а "один план, много субагентов, много PR".
