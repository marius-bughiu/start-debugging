GitHub опубликовал две записи в changelog с разницей в один день, которые вместе меняют и то, что просматривает Copilot code review, и то, во сколько это обходится. 27 августа 2026 года исчезло ограничение на размер ревью, а pull request, созданные ботами, стали доступны для проверки. 28 августа 2026 года GitHub объявил, что **28 сентября 2026 года** уровень усилий по умолчанию меняется с Lite на Balanced. Ни одно из этих изменений не требует согласия.

## Три множителя в одном месяце

Запись от 27 августа, [Copilot code review: resolution reasons and expanded capabilities](https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities/), убрала потолок, на котором ревью раньше останавливалось: 300 файлов или 20 000 строк кода. Крупные рефакторинги и PR со сгенерированным кодом, которые Copilot молча пропускал, теперь проверяются целиком. Та же запись сделала pull request, созданные ботами, пригодными для автоматического ревью, явно включая Copilot cloud agent, так что PR, открытые агентами, теперь проходят через ревьюера, а не попадают сразу в очередь к человеку.

Затем [запись о политиках и биллинге](https://github.blog/changelog/2026-08-28-upcoming-changes-to-github-copilot-policies-and-billing/) меняет уровень усилий по умолчанию. Документация GitHub прямо описывает компромисс: Lite это "standard review", Balanced выполняет "deeper analysis of complex logic, security-sensitive code, and cross-service changes", а ревью уровня Balanced "use more AI credits, and may consume marginally more GitHub Actions minutes."

Больше проверяемых PR, более крупные diff на каждое ревью и более глубокий проход модели по каждому из них. Если бюджет на AI-кредиты рассчитывался по июльскому счёту, сентябрь с ним не совпадёт.

## Зафиксируйте Lite до 28 сентября, если нужно текущее поведение

Уровень усилий существует и на уровне организации, и на уровне репозитория, причём настройка репозитория имеет приоритет. Settings, затем Copilot, затем Code review, в разделе "Code, planning, and automation". Явно выставленный Lite до 28 сентября сохраняет текущее поведение; если настройку не трогать, включится Balanced.

Заодно стоит проверить флаг `review_on_push` в ваших ruleset. Он запускает повторное ревью на каждый push, поэтому умножается на более глубокий уровень по умолчанию, а не складывается с ним. Тип правила называется `copilot_code_review`, так что его можно проверить, не заходя в каждый репозиторий вручную:

```bash
gh api /repos/OWNER/REPO/rulesets --jq '.[].id' \
  | xargs -I{} gh api /repos/OWNER/REPO/rulesets/{} \
      --jq '.rules[] | select(.type=="copilot_code_review")'
```

Правило, срабатывающее на каждый push, выглядит так:

```json
{
  "type": "copilot_code_review",
  "parameters": {
    "review_on_push": true,
    "review_draft_pull_requests": true
  }
}
```

В ветке, куда пушат шесть раз до запроса ревью, `review_on_push` вместе с `review_draft_pull_requests` дают шесть ревью уровня Balanced по diff, на который ещё никто не смотрел.

## Причины закрытия наконец делают комментарии измеримыми

Единственное однозначно хорошее изменение: закрытие комментария из ревью Copilot теперь требует указать причину в выпадающем списке рядом с "Resolve conversation". Доступны варианты **Addressed**, **Won't fix** и **Incorrect**. Именно третье значение важно, потому что доля ложных срабатываний автоматического ревью впервые становится числом, которое можно выгрузить, а не ощущением ваших senior-инженеров. Прежде чем включать Balanced по всем репозиториям, потратьте спринт на разметку причин в режиме Lite и посмотрите на реальное соотношение.

Ещё две даты из той же записи: новые назначения мест Business и Enterprise требуют оплаты до предоставления доступа начиная с 1 сентября 2026 года, существующие клиенты увидят предоплату за места с 1 октября 2026 года, а единый интерфейс Copilot, выходящий 28 сентября, продлевает хранение данных чата с 28 дней до всего срока жизни аккаунта. Последнее включено по умолчанию, а отказ полностью лишает Copilot Chat на github.com и в мобильном приложении, так что это вопрос комплаенса, а не предпочтений.
