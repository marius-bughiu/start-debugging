2026-08-03 GitHub выпустил [Trigger Copilot automations with comments](https://github.blog/changelog/2026-08-03-trigger-copilot-automations-with-comments/). Автоматизации облачного агента Copilot теперь могут срабатывать при создании комментария в issue или в pull request, сопоставляясь с текстом комментария, который вы задаёте. Это однострочная запись в changelog, которая убирает удивительно много YAML.

## Прежний набор триггеров был про события, а не про обсуждение

Автоматизации появились 2026-06-02 с четырьмя триггерами: по расписанию (ежечасно, ежедневно или еженедельно), при создании issue, при открытии pull request и при синхронизации pull request. Каждый из них срабатывает в момент, когда что-то переходит в определённое состояние. Ни один не покрывает сценарий, к которому команды на самом деле обращаются: человек сначала читает обсуждение, а потом говорит "поехали".

Поэтому связующий код вы писали сами. Форма всегда была одна и та же: workflow на `issue_comment`, проверка строки, токен и `POST` в [Agent Tasks REST API](/2026/06/trigger-github-copilot-coding-agent-task-from-rest-api/).

```yaml
name: copilot-on-comment
on:
  issue_comment:
    types: [created]

jobs:
  dispatch:
    if: startsWith(github.event.comment.body, '/copilot fix')
    runs-on: ubuntu-latest
    steps:
      - name: Dispatch an agent task
        env:
          GH_USER_TOKEN: ${{ secrets.COPILOT_USER_TOKEN }}
        run: |
          curl -X POST \
            -H "Accept: application/vnd.github+json" \
            -H "X-GitHub-Api-Version: 2026-03-10" \
            -H "Authorization: Bearer $GH_USER_TOKEN" \
            https://api.github.com/agents/repos/${{ github.repository }}/tasks \
            -d '{
              "prompt": "Investigate the stack trace in issue #${{ github.event.issue.number }} and open a fix PR.",
              "base_ref": "main",
              "create_pull_request": true
            }'
```

Каждая строка здесь требует сопровождения. `secrets.COPILOT_USER_TOKEN` должен быть токеном типа user-to-server, потому что встроенный `GITHUB_TOKEN` не запускает задачи агента, и срок его действия истекает по чьему-то календарю. Проверка сделана как простое совпадение префикса, поэтому `/copilot fixup` тоже её проходит. `X-GitHub-Api-Version: 2026-03-10` фиксирует публичную предварительную версию, формат ответа которой может измениться. А поскольку фраза-триггер лежит в файле, её изменение это pull request.

## Как вместо этого выглядит конфигурация

Откройте вкладку **Agents** в репозитории, выберите **Automations** в боковой панели и нажмите **Create new**. Автоматизация состоит из имени, промпта, одного или нескольких триггеров, необязательной модели и набора инструментов. С новым триггером вы указываете, какой текст комментария должен её запускать, и это вся интеграция. Ни токена, ни файла workflow, ни заголовка версии API.

Список инструментов это место, где нужна настоящая осмысленность. Это граница прав для запуска, а не настройка удобства: она определяет, к чему агент может прикоснуться, когда комментарий его разбудил. Кнопка **Suggest tools** предложит набор на основе вашего промпта, но воспринимайте это как отправную точку и урезайте до того, что задаче действительно нужно.

## Ограничения, которые стоит проверить до планирования

Автоматизациям нужен **приватный или внутренний** репозиторий. В публичных репозиториях они недоступны, поэтому проект с открытым кодом не сможет использовать это для разбора входящих issue. Для создания нужен доступ на запись, план должен быть Copilot Pro, Pro+, Max, Business или Enterprise, а в Business и Enterprise администратор должен сначала включить политику облачного агента. Кнопка **Run now** позволяет протестировать автоматизацию до того, как её запустит реальный комментарий.

Об одном последствии стоит подумать отдельно. Раньше запуск агента требовал токена, который сопровождающий выдавал осознанно. Теперь любой, кто может оставить комментарий в issue репозитория, может расходовать время агента. Приватная или внутренняя видимость ограничивает радиус поражения, но фразу-триггер держите специфичной, а список инструментов узким.
