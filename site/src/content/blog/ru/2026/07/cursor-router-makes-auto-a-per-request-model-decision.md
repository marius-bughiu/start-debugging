Cursor выпустил [Cursor Router](https://cursor.com/blog/router) 2026-07-22, и это незаметно меняет смысл настройки модели Auto. Раньше Auto была единой политикой маршрутизации, нацеленной на снижение расхода токенов. Теперь это система принятия решений, которая стоит перед всеми моделями вашей учётной записи, классифицирует каждый запрос по типу задачи и сложности и выбирает модель для этого конкретного запроса.

## Три режима, три разных счёта

В выборе модели вы указываете Auto, а затем режим в разделе "Optimize For". [Документация](https://cursor.com/docs/cursor-router) описывает их так:

- **Cost** использует прежнюю логику маршрутизации Auto. Он оптимизирует расход токенов и сохраняет пакетную тарификацию Auto, оплата за миллион токенов.
- **Balance** оптимизирует интеллект, скорость и стоимость и тарифицируется за запрос по ставке той модели, на которую пришлась маршрутизация.
- **Intelligence** направляет более сложные задачи к самым способным моделям и обходится дешевле, чем работа на одной фронтирной модели. Тоже оплата за запрос.

Именно оплату за запрос стоит перечитать дважды. Cost остаётся единственным режимом с пакетной ставкой. Cursor указывает, что Balance и Intelligence в среднем стоят примерно вдвое дороже Cost, а в зависимости от выбранного режима до двух-четырёх раз дороже.

Компромисс здесь реальный, а не маркетинговый. Cursor сообщает, что клиенты раннего доступа сократили расходы на 30-50 процентов по сравнению с использованием Opus 4.8 для всего, при стоимости на коммит 6.76 USD в режиме Intelligence и 4.63 USD в Balance. Intelligence по удовлетворённости пользователей близок к Fable примерно при 60 процентах меньшей стоимости для команд, а Balance превосходит Opus 4.8 примерно при 36 процентах меньшей стоимости.

## Выбранная маршрутизатором модель по умолчанию скрыта

В панели управления есть настройка, которая показывает в начале каждого ответа, на какую модель Auto направил запрос. По умолчанию она скрыта, и Cursor рекомендует так и оставить.

Для повседневной работы это нормально. Для тех, кто пытается разобраться в поведении агента, нет. Когда один и тот же промпт в понедельник даёт чистый рефакторинг, а во вторник посредственный, разница может быть в выбранной модели, и по умолчанию в стенограмме об этом ничего нет. Если вы оцениваете маршрутизатор перед развёртыванием на команду, сначала включите отображение и не выключайте его до конца испытания.

## Фиксируйте модель, когда запуск должен быть воспроизводимым

Маршрутизация хороша для интерактивной работы и плоха для всего, что вы сравниваете с базовой линией. Для запусков в CI, для оценочных стендов и скриптовых задач агента фиксируйте явную модель вместо наследования Auto:

```bash
# see the exact model ids this account exposes
agent --list-models

# pin one for a run that has to be repeatable
agent -p "run the failing tests and fix them" \
  --model <id-from-list-models> \
  --output-format json
```

Cursor Router работает на десктопе, в вебе, на iOS, в CLI и в SDK. В планах Teams он включён по умолчанию, администраторы Enterprise включают его из панели управления, а индивидуальные планы (Hobby, Pro, Pro+, Ultra) получат его через несколько месяцев после запуска. Администраторы могут ограничить набор доступных участникам режимов, задать режим по умолчанию, разрешить или заблокировать конкретные базовые модели, а также мягко или жёстко закрепить стандарт на Auto.

Если ваша команда уже опирается на параллельную работу агентов, например на [боковые чаты, появившиеся в Cursor 3.11](/ru/2026/07/cursor-3-11-side-chats-parallel-agent-threads/), маршрутизатор разом меняет структуру расходов на всё это. Проверьте режим, заданный вашим администратором, прежде чем считать, что счёт остался прежним.
