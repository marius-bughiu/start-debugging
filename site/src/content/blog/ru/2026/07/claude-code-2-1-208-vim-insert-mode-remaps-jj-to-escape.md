Claude Code 2.1.208 вышел 14 июля 2026 года, и в выпуске, который в основном состоит из исправлений ошибок, спрятана небольшая функция удобства, которую пользователи vim воссоздают вручную уже два десятилетия: `vimInsertModeRemaps`. Она позволяет назначить двухклавишную последовательность режима вставки, такую как `jj`, на Escape, чтобы вы могли выйти из режима вставки, не тянувшись к настоящей клавише Escape.

## Почему jj на Escape - это мышечная память

Если вы пользуетесь vim, у вас почти наверняка есть это в вашей конфигурации:

```vim
inoremap jj <Esc>
```

Причина эргономическая. Escape находится в дальнем углу клавиатуры, и тянуться к нему десятки раз в минуту нарушает ваш поток. Поскольку `jj` - это диграф, который почти никогда не встречается в прозе или коде, переназначение его на Escape позволяет вашим пальцам оставаться на основном ряду. Наберите `j` дважды в быстрой последовательности, и вы вернётесь в обычный режим.

В Claude Code уже некоторое время был режим редактирования vim для ввода промптов, который включается командой `/vim` или задаётся постоянно в настройках. Чего не хватало, так это какого-либо способа настроить выходы из режима вставки. Если ваши пальцы ожидали, что `jj` сработает, вы вместо этого получали два буквальных символа `j` в промпте. Версия 2.1.208 закрывает этот пробел.

## Как включить

Настройка находится в вашем файле `settings.json` для Claude Code. Включите режим vim, а затем объявите переназначения:

```json
{
  "editorMode": "vim",
  "vimInsertModeRemaps": {
    "jj": "escape"
  }
}
```

Механика соответствует поведению vim, которое вы уже знаете: две клавиши должны прийти в быстрой последовательности, чтобы засчитаться как последовательность. Наберите `j` отдельно и сделайте паузу, и он останется буквальным `j`. Именно это делает `jj`, `jk` или `kj` безопасным выбором. Они почти никогда не встречаются естественным образом, поэтому переназначение не съедает символы, которые вы действительно хотели набрать. Выберите ту пару, которой ваши руки научились из вашего существующего vimrc.

Это удобство редактора промптов, а не общая система назначения клавиш. Она сопоставляет последовательности режима вставки с Escape, чтобы вы могли вернуться в обычный режим и использовать движения vim для редактирования длинного промпта перед его отправкой. Если вы составляете инструкции в несколько абзацев для агента, именно там и было трение.

## Ещё две вещи в 2.1.208

В том же выпуске добавлен режим программы чтения с экрана: необязательный рендеринг в виде простого текста для пользователей программ чтения с экрана, включаемый с помощью `claude --ax-screen-reader`, переменной окружения `CLAUDE_AX_SCREEN_READER=1` или `"axScreenReader": true` в настройках.

Для закрытых корпоративных сред 2.1.208 вводит `CLAUDE_CODE_PROCESS_WRAPPER`. Представление агента и фоновая служба теперь направляют каждый самозапуск Claude Code через обязательный wrapper-исполняемый файл, чтобы организация могла навязать собственный лаунчер процессам, которые Claude Code запускает самостоятельно.

Остальная часть выпуска - это примерно 32 исправления в окнах контекста, соединениях HTTP/2, файловых операциях, sandboxing и рендеринге таблиц markdown. Но `vimInsertModeRemaps` - это та, что заставит пользователя vim улыбнуться. Полные заметки находятся в [changelog Claude Code](https://code.claude.com/docs/en/changelog).
