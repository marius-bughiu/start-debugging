Claude Sonnet 5 (`claude-sonnet-5`) вышел 2026-06-30, и это не предварительная версия, которую нужно включать вручную. В API Anthropic алиас `sonnet` теперь разрешается в него, а в Claude Code это модель по умолчанию для подписочных мест Pro, Team Standard и Enterprise. Это значит, что многие уже используют её, не изменив ни строки конфигурации. Загвоздка в том, что "прямое обновление" не означает "та же математика токенов", и если вы вручную оцениваете стоимость или задаёте размер `max_tokens`, то числа, настроенные под Sonnet 4.6, теперь неверны.

## Токенизатор изменился незаметно для вас

Sonnet 5 поставляется с новым токенизатором. Тот же входной текст даёт примерно на 30% больше токенов, чем на Sonnet 4.6. Цена за токен не изменилась, $3/$15 за миллион входных/выходных токенов (с вводной ценой $2/$10, действующей до 2026-08-31), но на 30% больше токенов для идентичного текста означает, что стоимость эквивалентного запроса растёт, хотя прайс-лист не изменился.

Три величины, которые вы измеряете в токенах, смещаются:

- **Стоимость запроса.** Любая оценка, выведенная из подсчёта токенов Sonnet 4.6, теперь занижена.
- **Бюджеты `max_tokens`.** Лимит вывода, заданный близко к ожидаемому ответу, может обрезаться на Sonnet 5, потому что тот же ответ расходует больше токенов.
- **Ёмкость контекста в терминах текста.** Окно составляет 1M токенов, но каждый токен в среднем покрывает меньше текста, поэтому то же окно вмещает меньше прозы.

Не экстраполируйте. Пересчитайте против модели с помощью эндпоинта подсчёта токенов, прежде чем доверять любому бюджету:

```bash
curl https://api.anthropic.com/v1/messages/count_tokens \
  --header "x-api-key: $ANTHROPIC_API_KEY" \
  --header "anthropic-version: 2023-06-01" \
  --header "content-type: application/json" \
  --data '{
    "model": "claude-sonnet-5",
    "messages": [{ "role": "user", "content": "Summarize this build log." }]
  }'
```

Выполните тот же payload против `claude-sonnet-4-6` и сравните `input_tokens`. Эта разница и есть ваша поправка к бюджету.

## Три поведения API, которые теперь дают 400

Если вы вызываете Sonnet 5 напрямую, три запроса, которые работали на Sonnet 4.6, теперь возвращают `400`:

- **Параметры сэмплирования.** Установка `temperature`, `top_p` или `top_k` в нестандартное значение отклоняется. Уберите их и направляйте модель через системный prompt.
- **Ручное расширенное мышление.** `thinking: {"type": "enabled", "budget_tokens": N}` убрано. Используйте адаптивное мышление, которое включено по умолчанию.
- **Prefill ответа ассистента.** По-прежнему не поддерживается, без изменений по сравнению с Sonnet 4.6.

## Что это значит внутри Claude Code

Sonnet 5 требует Claude Code v2.1.197 или новее; выполните `claude update`, если `sonnet` всё ещё разрешается в 4.6. В API Anthropic он всегда работает с нативным окном контекста 1M, без суффикса `[1m]` и без кредитов использования, а сессии автоматически уплотняются примерно на 967K токенов. Если для контроля стоимости вам нужен жёсткий потолок в 200K, задайте `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. А если вы хотите точно контролировать, когда ваша команда переходит между версиями, зафиксируйте полный ID вместо того, чтобы полагаться на алиас:

```json
{
  "model": "claude-sonnet-5"
}
```

Сама миграция действительно сводится к замене ID модели в одну строку. Работа же заключается в бюджетах вокруг неё. Все подробности приведены в [примечаниях к выпуску Sonnet 5](https://platform.claude.com/docs/en/about-claude/models/whats-new-sonnet-5).
