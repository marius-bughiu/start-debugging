Большую часть прошлого года инструменты модернизации .NET от GitHub Copilot имели единственный дом: Visual Studio. Если ваша команда жила в VS Code, работала в командной строке или проверяла всё через pull request, опыт "обнови мое устаревшее приложение" находился там, где вы не работали. 2026-07-09 Microsoft [выпустила агент `modernize-dotnet` как переносимый плагин](https://devblogs.microsoft.com/dotnet/modernize-dotnet-anywhere-with-ghcp/), который работает на четырёх поверхностях: Visual Studio, VS Code, CLI GitHub Copilot и самом GitHub.

## Почему "где угодно" здесь действительно важно

Модернизация не является командой из одного шага. Это оценка, планирование, а затем длинная последовательность преобразований кода, которую вы контролируете. Загон этого в единственную IDE означал, что человек, ведущий обновление, был вынужден переключать контекст за пределы своей привычной среды ради работы, которая часто длится несколько дней. Перенос того же агента в CLI позволяет разработчикам, предпочитающим терминал, запускать его рядом со своим циклом сборки и тестирования, а размещение его на GitHub позволяет обновлению происходить как проверяемая, совместная единица работы, а не как локальная сессия одного человека.

Рабочий процесс одинаков везде, и в этом суть. Агент следует модели оценить, спланировать и выполнить и записывает в ваш репозиторий три артефакта:

1. **Оценку**, которая раскрывает объём и блокеры до любых изменений кода.
2. **План обновления**, который упорядочивает работу.
3. **Задачи обновления**, которые применяют реальные преобразования.

Поскольку эти артефакты фиксируются в репозитории, ваша команда проверяет план так же, как проверяет PR, до того как выполнение затронет хотя бы одну строку кода.

## Запуск из CLI Copilot

Путь через CLI устанавливает агент как плагин, а затем управляет им на естественном языке. Команды короткие:

```bash
# Add the plugin marketplace and install the agent
/plugin marketplace add dotnet/modernize-dotnet
/plugin install modernize-dotnet@modernize-dotnet-plugins

# Select the agent, then describe the job
/agent modernize-dotnet
upgrade my solution to a new version of .NET
```

Дальше агент генерирует оценку, предлагает план и применяет задачи с одобрением человека в цикле на каждом шаге. Он берёт на себя неприглядные части обновления: поднятие target framework, обновление зависимостей и исправление ошибок компиляции, которые оставляет после себя изменение `TargetFramework`.

## Что он охватывает сегодня

Поддерживаемые рабочие нагрузки включают ASP.NET Core, Blazor, Azure Functions, WPF, библиотеки классов и консольные приложения, а также миграции с .NET Framework на современный .NET. Web Forms пока не входит в область охвата. Если вы раньше пробовали версию только для Visual Studio и находили её неудобной для встраивания в командный рабочий процесс, это тот релиз, который исправляет модель поставки, а не возможности.

Агент разрабатывается открыто в [dotnet/modernize-dotnet](https://github.com/microsoft/github-copilot-appmod), и развёртывание на четырёх поверхностях уже доступно. Интересный сдвиг не в том, что Copilot умеет обновлять код .NET, а в том, что обновление теперь является артефактом репозитория, который вы проверяете, а не чёрным ящиком внутри одного редактора.
