Последние две недели релизов Claude Code были перетягиванием каната вокруг того, сколько свободы дать флоту агентов. Версия 2.1.213 полностью убрала вложенность. Версия 2.1.219, вышедшая 2026-07-24, возвращает её с конкретным числом: субагенты теперь могут порождать собственные субагенты до глубины 3 по умолчанию вместо 1.

## Значение по умолчанию менялось дважды за две недели

Строка в [changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) сформулирована прямо: "субагенты теперь могут порождать вложенные субагенты до глубины 3 по умолчанию (было 1); задайте CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1, чтобы отключить вложенность".

Историю стоит проследить, потому что поведение менялось трижды. С v2.1.172 по v2.1.216 субагенты вкладывались до пяти уровней, и предел нельзя было настроить. Затем 2.1.213 [ввела жёсткие лимиты на вышедшие из-под контроля флоты субагентов](/ru/2026/07/claude-code-2-1-213-caps-runaway-subagent-fleets/) и опустила значение по умолчанию до глубины 1, то есть субагент вообще не мог делегировать: попросишь его поднять помощников, а он делает работу сам. В 2.1.219 остановились на 3.

Сама ручка не изменилась, сдвинулось только её значение по умолчанию. Чтобы вернуться к плоскому делегированию в один уровень, зафиксируйте его в `settings.json`:

```json
{
  "env": {
    "CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "1"
  }
}
```

Глубина 3 выбрана осознанно, а не для круглого счёта. Это ровно то, что нужно развёртыванию ревью: основной диалог порождает ревьюера, ревьюер порождает по верификатору на каждую находку, и каждый верификатор всё ещё может делегировать точечный поиск. При глубине 1 такая схема схлопывалась в один субагент, который делал всё последовательно в одном контекстном окне.

## Ориентир по размеру как противовес

Вернуть вложенность без тормоза означало бы просто воссоздать проблему, которую закрыла 2.1.213, поэтому тот же релиз тормоз добавляет. Динамические рабочие процессы теперь по умолчанию используют средний ориентир по размеру с целью менее 15 агентов, и этот ориентир больше не только переключатель в `/config`. Для него появился ключ настроек:

```json
{
  "workflowSizeGuideline": "medium"
}
```

Задайте его в любом файле настроек, и строка в `/config` скроется сама. Строка состояния выполняющегося рабочего процесса теперь тоже печатает текущий размер, так что видно, под каким ориентиром он работает прямо по ходу. Учтите, что это рекомендация: она задаёт, к какому числу агентов стремится модель, а не жёсткий потолок. Настоящие потолки по-прежнему задают лимиты параллелизма и числа субагентов на сессию.

## Сетевые allowlist, которые блокируют по умолчанию

Второе изменение, которое стоит настроить сегодня, это `sandbox.network.strictAllowlist`. По умолчанию песочница спрашивает, когда команда впервые обращается к домену, который вы не разрешали. Управляемые развёртывания уже могли блокировать вместо запроса через `allowManagedDomainsOnly`. Теперь так может любой файл настроек:

```json
{
  "sandbox": {
    "enabled": true,
    "network": {
      "strictAllowlist": true,
      "allowedDomains": ["github.com", "*.npmjs.org"]
    }
  }
}
```

Для запусков без присмотра это именно та настройка, которая нужна. Запрос, на который некому ответить, превращается в зависание, а с вернувшейся вложенностью процессов, способных на него наткнуться, стало больше.

Также в 2.1.219: Claude Opus 5 (`claude-opus-5`) стал моделью Opus по умолчанию с контекстом 1M и быстрым режимом по $10/$50 за Mtok, а Opus 4.7 полностью выведен из быстрого режима.
