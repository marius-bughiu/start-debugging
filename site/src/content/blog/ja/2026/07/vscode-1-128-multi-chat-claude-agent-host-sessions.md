VS Code 1.128 は 2026 年 7 月 8 日にリリースされましたが、目玉は Copilot の機能ではありません。1 つの Claude agent-host セッションが、関連する複数のチャットを同時に保持できるようになったことです。各チャットは独自の履歴、タイトル、モデル選択を持ち、すべてが 1 つの親セッションの下にまとめられます。agent-host モードは、VS Code 内で直接動作する Anthropic の Claude Agent SDK によって動いており、このリリースはそれを単一スレッドの体験から、作業台に近いものへと変えます。

## 複数チャットを持つ 1 つのセッションがなぜ重要か

1.128 より前は、同じ問題に対して 2 つのアプローチを試すには、スレッドの途中で方向転換してコンテキストを台無しにするか、まったく新しいセッションを立ち上げて共有のセットアップを失うかのどちらかでした。複数チャットはこれを解決します。以前のターンから分岐し、元のチャットをそのまま保ちながら、両方を並行して実行できます。各チャットは独自のモデルを追跡するため、同じタスクで安価なモデルと強力なモデルを競わせ、セッションを離れずに diff を並べて比較できます。

これは agent-host モードに紐づいています。`settings.json` で有効にします。

```json
{
  "chat.agentHost.enabled": true
}
```

これを設定すると、**Agents** ウィンドウがハブになります。新しいチャットは親セッションの下の **Chats** セクションに表示され、`workbench.action.openAgentsWindow` コマンドでウィンドウにフォーカスします。

## quick chat がワークスペースの要件をなくす

摩擦を取り除く 2 つ目の変更が quick chat です。フォルダーを先に開かなくても、Agents ウィンドウから会話を始められるようになりました。これは些細に聞こえますが、現在開いているプロジェクトとは無関係なことをエージェントに尋ねたい場面がどれほど多いか、そしてこれまではそのためにスクラッチ用のワークスペースを開く必要があったことを考えると、意味が分かります。quick chat は agent-host セッションでのみサポートされるため、同じ `chat.agentHost.enabled` スイッチに乗ります。

サブエージェントにも触れておきます。agent-host はサブエージェントに委任でき、サブエージェントのトランスクリプトは読み取り専用で閲覧するため、委任によって親チャットの履歴が汚染されることはありません。

## 独自のモデルキーを持ち込む

同梱の経路ではなく自前のモデルプロバイダー経由でルーティングしたいチームのための、実験的な設定もあります。

```json
{
  "chat.agentHost.byokModels.enabled": true
}
```

BYOK サポートは 1.128 では実験的と位置付けられているため、今週チームで標準化するものではなく、プレビューとして扱ってください。より安価なユーティリティ呼び出しをどのモデルが処理するかを制御したい場合は、`chat.byokUtilityModelDefault` と組み合わせてください。

リリースの締めくくりとして、Copilot Vision が一般提供になりました。画像や PDF を Chat に貼り付け、ドラッグ、ドロップする操作はもうプレビューではなく、エージェントはツール呼び出しを通じてそれらの添付ファイルにアクセスできます。

複数チャットの部分が、最初に試す価値のあるものです。すでに VS Code で Claude の agent-host を実行しているなら、`chat.agentHost.enabled` を有効にし、Agents ウィンドウを開いて、チャットを再起動する代わりに分岐してみてください。詳細は [VS Code 1.128 リリースノート](https://code.visualstudio.com/updates/v1_128)にあります。
