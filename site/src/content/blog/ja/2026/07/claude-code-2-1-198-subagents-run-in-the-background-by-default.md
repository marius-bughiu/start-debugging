Claude Code v2.1.198 は 2026-07-01 にリリースされ、サブエージェントのデフォルトの実行モデルを変更します。これまでは、サブエージェント (Task ツール、カスタムエージェント、エージェントチーム) を起動するとメインループがブロックされていました。作業の一部を委譲すると親エージェントは沈黙し、子が返ってくるまで他の何も動きませんでした。2.1.198 からは、サブエージェントはデフォルトでバックグラウンドで実行され、実行中もメインエージェントが作業を続けます。

## なぜブロックはデフォルトとして誤りだったのか

サブエージェントの目的は分離です。親がファイルのダンプに溺れないよう、独自のコンテキストウィンドウを持つ自己完結したジョブ (ディレクトリを走査する、主張を検証する、マイグレーションを起草する) を渡します。しかし、起動すると子が終わるまで親が凍りついてしまうなら、もう一方の利点である並列性を失います。同時に実行できたはずの 2 つの独立したクエリが次々と実行され、実時間のコストは最大値ではなく合計になっていました。

デフォルトでのバックグラウンド実行はこれを修正します。親は作業を振り分け、メインスレッドで作業を続けます。子が終わると、その結果は、あなたが後ろで待たされる壁としてではなく、対応できる通知として返ってきます。分解できるものであれば、これはパイプラインとキューの違いに相当します。

## 仕事をやり切るバックグラウンドエージェント

このリリースの後半は、バックグラウンドエージェントが完了時に何をするかです。バックグラウンドエージェントが git worktree でコード作業を行った場合、diff をどう扱うかを尋ねるために止まることはもうありません。自動で commit、push し、draft PR を開いてから報告します。

これは実際のワークフローの変化です。古いループはこうでした。エージェントを起動し、待ち、提案された変更をレビューし、それから自分で commit、push する。新しいループはこうです。エージェントを起動し、作業を続け、変更が届いたときにレビュー待ちの draft PR を見つける。ドラフト状態が安全のためのガードレールです。何も勝手にマージされませんが、「エージェントが終わった」から「本物の PR をレビューできる」までの配管はなくなりました。

```bash
# Before 2.1.198: foreground subagent, main loop blocks until it returns.
# You then stage and push its changes by hand.

# 2.1.198+: subagent runs in the background, you keep working, and a
# code-writing background agent lands its work as a draft PR itself:
#   [background] agent "refactor-auth" finished
#   -> committed, pushed branch agent/refactor-auth, opened draft PR #482
```

デフォルトが変わったので、サブエージェントが同期的であると前提していた自動化やドキュメントを読み直す価値があります。次の行が実行される前にサブエージェントが終わることに暗黙的に依存していたステップは、いまや結果を明示的に待つ必要があります。

## 2.1.198 のその他の内容

同じリリースには他に 2 つの項目があります。Claude in Chrome が一般提供になり、ブラウザを操作するツールがプレビューから外れました。そして、グラフやダッシュボードを作るための新しい `/dataviz` スキルが追加されました。このリリースは一時的なエラーに対するネットワークの堅牢性も強化し、バックグラウンドタスク、エージェントチーム、Remote Control の一連のバグを修正しています。これは [2.1.200 のバックグラウンドセッション修正](/ja/2026/07/claude-code-2-1-200-renames-default-permission-mode-to-manual/)へと続いたのと同じ信頼性向上の流れです。

サブエージェントに少しでも頼っているなら、見出しは言葉にすれば短く、実際には大きいものです。もう待たされません。詳細は [Claude Code の changelog](https://code.claude.com/docs/en/changelog) にあります。
